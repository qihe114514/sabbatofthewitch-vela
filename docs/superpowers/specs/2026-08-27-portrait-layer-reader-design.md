# 立绘与表情同画布阅读器设计

## 目标

从原作本体和汉化补丁重新提取剧本、立绘、表情及事件图，确保每个对白角色键 `角色|表情|服装` 只绑定到同一套原作资源；表情覆盖与身体使用同一源画布和同一缩放比例，运行时只使用 PNG。

## 资源管线

提取器读取 `bgimage.xp3`、`fgimage.xp3`、`evimage.xp3`、`data.xp3`、`scn.xp3` 及 `patch.xp3` 到 `patch4.xp3`。同一归档路径按本体到补丁的顺序覆盖，最终输出 manifest 记录来源归档、内部路径和覆盖关系。剧本优先使用补丁中的 `.scn/.ks`，图像优先使用补丁中的同名资源。

角色构建以 `fgimage` 的层描述和 `_info.txt` 为唯一坐标源：身体层与表情层都绘制到相同原始画布，再一起裁剪、缩放到手环上限。manifest 同时记录 body/face 的 `canvas`、`crop` 和 `sourceKey`，生成器拒绝没有对应身体或画布不一致的脸。

## 阅读器

解析器返回 `{ body, face, canvas }` 的 portrait 记录。阅读器每个位置只渲染一个 portrait 容器，容器内的 body 与 face 使用完全相同的尺寸和 `object-fit`；不再对脸单独设置位置或缩放。未找到精确角色键时显示缺失资源提示，不回退到其他角色或随机同名图。

## 校验

校验脚本检查：所有剧本角色键都有 body；face（如存在）与 body 的画布元数据完全一致；`src/common` 下图片扩展名全部为 `.png`；manifest 的每个路径均存在。测试覆盖补丁覆盖、角色键精确匹配、同画布合成和 PNG-only。
